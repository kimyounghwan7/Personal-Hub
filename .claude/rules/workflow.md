# 작업 방식 — 모든 작업에 적용

이 repo 의 결과는 대화가 아니라 파일로 남긴다. 세션은 끝나면 잊는다.

## 시작과 끝
- 시작: `docs/status.md` 를 읽는다. 확정된 결정은 `docs/decisions.md` 에서 확인한다.
- 다음 작업을 제안하기 전에 `docs/status.md` §1 의 진행 순서(사용자가 정한 것)와 대조한다.
- 작업을 보고할 때는 진행 순서에서 **지금 어디인지(단계 제목과 한 것/남은 것) · 다음에 할 것 · 지금 정해야 할 것**을 함께 쓴다. 대화 보고에서는 표를 그리지 않고 짧은 줄로 남긴다.
- 끝: 한 일과 다음 작업을 `docs/status.md` 이력·표에 반영한다. 점검·아키텍처·비용 분석은 `docs/reports/YYYY-MM-DD_주제.md` 로 남기고 `docs/reports/README.md` 색인에 한 줄을 더한다.
- 여러 걸음으로 이어지는 작업은 걸음마다 문서를 갱신하지 않고, 묶음이 끝났을 때 한 번에 `docs/status.md` 와 보고서를 갱신한다.
- 결정을 올리기 전에 **지금 단계에 필요한 결정인지** 본다. 결정이 필요한 것은 임의로 확정하지 않고 선택지 · 근거 · 비용/보안 영향을 정리해 사용자에게 올린다. 확정되면 `docs/decisions.md` 에 적는다.

## 방향을 정하는 순서
- 사용자가 방향을 주면 **큰 그림 초안을 먼저** 낸다 — md 파일에 mermaid 로 전체 모습(무엇이 어디에 · 어떻게 이어지나 · 비용/보안 경계가 어디인가)을 그린다.
- 사용자가 큰 그림으로 방향을 정한 뒤에 세부(선택지 · 코드 반영)로 들어간다.
- **미정인 것은 git 에 넣지 않는다.** 초안 · 선택지 · 결정 후보(`drafts/decision-candidates.md`)는 git 무시 폴더 `drafts/` 에 둔다. 확정된 순간에 가공해서 `docs/` · 코드에 반영한다(결정 WF-5).

## 검증
- 에러가 없다고 정상이 아니다. 결과로 판정한다(스키마가 일치하는가, HTTP 상태 코드와 응답 본문이 기대와 같은가, 보안 헤더가 실제로 붙는가).
- 검사는 빈 값을 실패로 친다.
- 확인 가능한 주장(코드 구조 · 패키지 설치 여부 · 환경변수 존재 여부 · 커밋 이력)은 직접 확인하고 쓴다.

## 허락이 필요한 것
- `docker build` · `docker compose up --build` · `alembic upgrade` · 클라우드 배포(Vercel / Render / Fly.io) · 도메인 DNS 변경.
- **린트 · 포매터 · 검사 규칙을 끄거나 완화하는 것 — 절대 혼자 하지 않는다**(결정 WF-6). ESLint 규칙 무시 · `noqa` · `type: ignore` · 보안 검사 예외 추가 모두 같다. 바꿔야 하면 무엇을 · 왜 · 결과를 먼저 알리고 항목 하나로 따로 승인받는다.
- git 은 아래 정책을 따른다(결정 WF-3). 훅 `.claude/hooks/git-policy.sh` 가 막거나 묻는다. 설정은 `.claude/git-policy.conf`.
  - 보호 브랜치(`PROTECTED_BRANCH`)로의 직접 push 는 막거나 묻는다.
  - 작업과 변경 성격별로 커밋을 구분해 쪼갠다(`git add -A` 일괄 묶음 금지): ① 백엔드/프론트엔드 기능·보안 코드 변경, ② 테스트·린트 정리, ③ 문서·규칙(`docs/`, `.claude/`) 갱신을 별도 커밋으로 나눈다.

## 에이전트 역할 분담 (Claude Code · Antigravity 공통)
- **단일 정본**: 규칙은 `.claude/rules/*.md`(`AGENTS.md` 가 `@[...]` 참조로 복제 없이 공유)에, 리뷰어 · 검증 에이전트 정의는 `.claude/agents/*.md`(`code-reviewer` · `auth-security-reviewer` · `docs-reviewer` · `verifier`) 한 곳에 둔다.
- **1단(개별 파일 수정 중)**: 로컬 기계적 가드(`comment-guard.sh` · `shape-guard.sh`)와 직접 `git diff` 점검으로 빠르게 진행한다.
- **2단(단계 종료 · 인증/배포/비용 설정 변경 직후)**: 누적된 변경 범위(`git diff`)와 문서를 묶어 `code-reviewer` · `auth-security-reviewer` · `docs-reviewer` 를 호출해 치명 지적만 수정한다(3회차 이상 STOP).

## 실수를 막는 습관
- **한 글자 이름을 쓰지 않는다** — 변수 · 인자 · 반복 변수는 어디서 읽어도 하는 일을 알 수 있게 쓴다(`_` 만 예외).
- **감싸지 않는다**(결정 WF-7) — 본문이 호출 하나뿐인 함수(단순 감싸기)는 부르는 자리에 두거나 인자로 주입한다. 파일을 고친 직후 훅(`shape-guard.sh`)이 HEAD 보다 늘면 되돌려 보낸다.
- `rm -rf` · `mv` · 덮어쓰기는 다른 명령과 한 블록에 묶지 않고 단독으로 실행한다(결정 WF-4, `destructive-guard.sh`).
